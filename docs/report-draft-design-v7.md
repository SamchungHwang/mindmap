# 투자 의사결정 마인드맵 — 설계 v7 (2026-10-27 초안 → 같은 날 검토 의견 반영 개정)

**한 줄 목표.** 지금 맵은 "증권사들이 얼마를 예상하는가" 까지 보여 준다. v7 은 거기서 두 걸음 더 간다 — **"그 가격이 성립하려면 무엇이 일어나야 하는가"** 와 **"어떤 증거가 나오면 내 판단을 수정해야 하는가"** 를 맵 안에 숫자와 날짜로 적는다.

이 문서는 사람이 읽는 설계서다. 코드 이름·필드 이름은 마지막 부록에만 모았다. 초안에 대한 검토 의견 세 가지(역산의 다중 해석 · 증거의 시계열 정합성 · 신호등과 BUY 규칙) 는 구현 가능성을 확인한 뒤 모두 반영했다 — 무엇이 어떻게 바뀌었는지는 §11 에 모았다.

## 0. 한 쪽 요약

맵 하나가 네 질문에 차례로 답하게 만든다.

| 질문 | 지금(v6) | v7 에서 |
|---|---|---|
| **Q1** 지금 가격과 증권사 가격은 무엇을 전제하는가 | 역산 한 줄 ("DRAM ASP −57% 내재") — 단정형, 단일 PER | **가정 표**(증권사가 실제로 적은 전망 + 내가 채택한 가정) 와 **역산 표**(한 변수 해 · 두 변수 조합) 를 **따로** 둔다. 역산은 전부 "다른 변수 고정 시" 조건부 |
| **Q2** 그 가격이 성립하려면 무엇이 일어나야 하는가 | 계산기에 사람이 가정을 넣으면 가격이 나온다 (거꾸로는 안 됨) | **필요 경로**: 가격에 가는 드라이버 값을 **날짜별 경로**로 — 증권사가 말한 경로 · 컨센 경로 · 내 경로 |
| **Q3** 어떤 증거가 나오면 판단을 바꿔야 하는가 | 드라이버마다 관측 지표·다음 확인일, Kill 조건 문장 | **증거 계획**: 관측값은 지표·기간·기준·출처·검증 등급이 붙은 **같은 자(尺)** 로만 비교 — 날짜별 필요 경로 대비 신호등. **판단 수정 규칙**: 드라이버의 **논제 역할**(필수·핵심·보조·Kill) 에 따라 다른 대응, 발동 → 검증 → 제안 → 승인 순 |
| **Q4** 그래서 지금 무엇을 하나 | 판단·비중·진입·손절 (사람) | 그대로 — 다만 "분석 판단"(BUY/WATCH/PASS) 과 "보유 대응"(B 맵) 과 "주문" 을 구분한 상태 전이표. 주문을 막는 기능은 없다 |

새로 생기는 것은 **표 다섯 개**(가정 표 · 역산 표 · 필요 경로 · 증거 계획 · 판단 수정 규칙) 와 **드라이버별 신호등**, 그리고 **관측값의 데이터 계약**이다. 노드 번호는 그대로 두고 두 개(A2.4 · A4.6) 만 더한다. 숫자는 전부 코드가 계산하고, 경계값·역할·판단은 사람이 적는다. LLM 은 리포트에서 "증권사가 무엇을 가정했는가" 를 읽어 올 뿐 가정 숫자를 만들지 않는다.

v6 검토에서 나온 세 가지 기반 수정(회계 기준 정규화 · 역산의 조건부 해석 · Claim 품질 게이트, v6 §11) 은 v7 의 **전제 조건**이다. 기준이 섞인 EPS 위에 필요 경로를 세우면 경로도 틀린다.

## 1. 목표와 원칙

### 1.1 맵이 답해야 하는 네 질문

투자 판단은 "얼마가 될까" 가 아니라 "무엇이 일어나야 얼마가 되고, 그것이 일어나고 있는지 어떻게 아는가" 다. 그래서 맵의 중심을 **가격** 에서 **조건과 증거** 로 옮긴다.

```
   증권사 목표가 530,000  ─┐
   현재가      262,000  ─┼─▶ Q1 가정 표 (증권사·내 가정) + 역산 표 (한 변수 해 · 두 변수 조합)
   내 목표가   (사람)   ─┘            │
                                      ▼
                          Q2 필요 경로: 날짜별로 DRAM ASP · HBM · 파운드리 · PER 가 가야 할 값
                                      │
                                      ▼
                          Q3 증거 계획: 같은 자로 잰 관측값 vs 날짜별 필요 경로 → 신호등
                              판단 수정 규칙: 역할별 대응 (보류 / 재계산 / 경고 / 폐기)
                                      │
                                      ▼
                          Q4 판단 상태: BUY / WATCH / PASS · 보류 · 재검토 (사람) → B 맵 대응
```

### 1.2 원칙 (v3~v6 의 원칙 위에 다섯을 더한다)

- **모든 가격은 조건부다.** "현재가는 X 를 내재한다" 라고 쓰지 않는다. "다른 변수를 고정하면 현재가를 설명하는 값은 X" 라고 쓰고, 같은 가격을 설명하는 조합이 여러 개라는 것을 **같은 화면에서** 보여 준다.
- **증거는 같은 자로만 잰다.** 지표·기간·값의 종류(절대값/증감률/누적/상태)·기준(QoQ/YoY/컨센 대비)·관측일·출처·검증 등급이 붙지 않은 숫자는 관측값이 아니다. 분기 증감률을 연간 경로와 비교하지 않고, 전망치를 실적처럼 쓰지 않는다.
- **판단 수정은 규칙으로 미리 적고, 발동과 판단 변경을 분리한다.** 규칙이 발동하면 먼저 검증(진위·기간·지속성) 을 거쳐 제안이 만들어지고, 사람이 승인해야 판단이 바뀐다. 자동으로 바뀌는 것은 "신규 BUY 보류" 플래그 하나뿐이고 그것도 필수 조건 위반일 때만이다.
- **드라이버는 역할이 다르다.** 필수 조건 · 핵심 수익 변수 · 보조 변수 · Kill 조건. 신호등을 세거나 점수로 더하지 않고 역할별로 대응한다.
- **숫자는 코드, 경계값·역할·판단은 사람, 추출은 LLM. 주가는 증거가 아니다.** 주가는 A6.3 손절 규칙에서만 쓰고, 증거 계획에는 사업 지표만 넣는다.

## 2. 지금(v6) 과 목표 사이의 거리

| 질문 | 있는 것 | 없는 것 |
|---|---|---|
| Q1 가정 | 역산(현재가 → EPS → 가격 드라이버 한 개) · 시나리오 = 가정 묶음 · 증권사 전망 Claim | 증권사가 **말한** 가정과 역산의 **수학적 해**가 한 줄에 섞여 있다. 두 변수 이상의 조합은 없다. 역산이 단일 PER·단정형(v6 §11.2 에서 고치기로) |
| Q2 필요 경로 | 가정 → 가격 (계산기) · 가격 드라이버 1개 역산 | **가격 → 가정** 의 역산이 가격·물량 템플릿에만 있다. 경로가 연간 한 점(2027E) 뿐이고 **중간 시점**이 없다. 증권사별 "그 목표가에 깔린 가정 묶음" 이 없다 |
| Q3 증거 | 드라이버마다 관측 지표 문장 · 다음 확인일 · 무효화 조건 문장 · Kill 규칙(사실) · 조기 경보 문장 | 관측값을 적는 칸이 없다(현재값은 리포트 수치). 관측값의 기간·기준·출처·검증 등급이 없다. 필요값·경계값이 없다. "넘으면 무엇을 바꾸나" 가 없다 |
| Q4 판단 | 판단·비중·진입·손절·익절 · RR 미달이면 BUY 금지 | 증거와 판단의 연결이 없다. 분석 판단과 보유 대응의 상태 전이가 적혀 있지 않다 |

## 3. 설계 — 표 다섯 개, 신호등, 상태 전이

### 3.1 가정 표 — "증권사는 무엇을 적었고, 나는 무엇을 채택했나"

가정 표에는 **실제로 적힌 것**만 들어간다. 리포트에서 읽은 증권사별 전망 수치(Claim 의 "전망" 셀), 그것을 같은 기준으로 모은 컨센, 그리고 내가 계산기에 넣은 가정. 역산으로 만든 숫자는 여기 들어오지 않는다.

| 드라이버 | IBK (TP 460,000) | 유진 (TP 560,000) | DS (TP 530,000) | 컨센 2027E (기준 통일) | 내 가정 (Base) |
|---|---|---|---|---|---|
| DRAM ASP · 매출 | 2027E DRAM 매출 ○조 | ○조 | ○조 | 458.5조 (2곳) | 컨센 +0% |
| HBM | 비중 ○% | 말하지 않음 | ○조 | 82.9조 (1곳 — 컨센 아님) | … |
| 파운드리 손익 | −○조 | −○조 | BEP 2028 | −0.57조 | … |
| 적용 PER | 목표 PER ○ (리포트 명시) | 말하지 않음 | ○ | 목표가 유도 6.18 (순환) | 사람이 넣은 PER |

칸이 비면 "말하지 않음" 이다(v4 의 침묵 구분). 한 곳만 적은 수치는 컨센이 아니라 그 증권사의 주장으로만 표시한다(v5). 이 표의 열이 그대로 §3.3 의 "증권사 경로" 가 된다.

### 3.2 역산 표 — "그 가격을 설명하는 조합들"

역산은 **수학적 해**다. 시장이 실제로 그렇게 믿는다는 뜻이 아니다. 그래서 가정 표와 분리해 두고, 표마다 **해석 범위**를 머리에 붙인다.

**① 한 변수 해 — 다른 변수 전부 고정.** 변수마다 "현재가 262,000 을 이 변수만으로 설명하면" 의 값과 도달 가능 범위.

| 변수 (다른 변수 고정) | 262,000 을 설명하는 값 | 범위 | 해석 |
|---|---|---|---|
| DRAM ASP (PER 6.18 고정) | 컨센 대비 −56% | 가능 | 다른 설명이 모두 틀렸을 때의 극단값 |
| 파운드리 손익 (PER 6.18 고정) | −○조 | **범위 밖** | 이 변수만으로는 설명 불가 |
| 적용 PER (실적 컨센 고정) | 3.05 | 가능 | "이익은 컨센대로, 시장이 지속성을 믿지 않음" 의 극단값 |

**② 두 변수 조합 — 같은 가격에 닿는 조합.** 기본 쌍은 **핵심 수익 변수 × 적용 PER** 이고 사람이 바꿀 수 있다. 한 변수의 격자마다 다른 변수를 풀어 표로 보인다.

| DRAM ASP (컨센 대비) | 적용 PER | 계산 주가 |
|---|---|---|
| 0% | 3.05 | 262,000 |
| −14% | 3.5 | 262,000 |
| −36% | 4.5 | 262,000 |
| −56% | 6.18 | 262,000 |

(설명용 — 정규화 전 민감도를 선형으로 쓴 값. 엔진 숫자는 W2 에서 나온다.) 이 표 하나로 "현재가는 DRAM ASP −57% 를 내재한다" 는 말이 왜 틀린지 보인다 — 같은 가격을 "이익은 컨센대로 + PER 3" 도, "ASP −36% + PER 4.5" 도 설명한다. 어느 조합이 실제 시장 기대에 가까운지는 §3.1 의 증권사 가정과 §3.4 의 관측값이 가려 주는 것이지 역산이 정하지 않는다.

**③ 해석 범위 표시.** 모든 역산 숫자에 네 가지 중 하나가 붙는다.

- **한 변수 해** — 나머지 변수 고정
- **두 변수 조합** — 사용자가 고른 쌍, 나머지 고정
- **증권사 경로** — 리포트에서 확인된 전망 (§3.1)
- **컨센 경로** — 여러 리포트를 같은 기준으로 집계한 전망 (v6 §11.1)

**풀 수 있는가.** 통합 1차 모델에서 가격은 각 변수에 **1차식(선형)** 이다 — 가격·물량의 교차항도 한 변수를 고정하면 선형이다. 따라서 이분 탐색이 아니라 **닫힌 식**으로 풀고, 기울기가 0 이면(사업부 매출이 없어 변수가 가격에 닿지 않으면) "해 없음 — 필요 입력: ○○" 으로, 해가 허용 범위(가격 −80%~+200% · 원가율 ±30%p · 손익 직접 ±|OP|×5) 밖이면 "범위 밖" 으로 표시한다. **환원(FCF·배당) 변수는 가격에 닿지 않으므로 역산하지 않고**(주당 환원만 계산), **수주 변수는 매출 전환 기간이 있어** 전환율·마진을 사람이 넣은 경우에만 "기간 구조 단순화" 표시와 함께 푼다. 검토 의견의 지적대로 "모든 템플릿에서 단조" 라고 쓰지 않는다 — 템플릿별로 위와 같이 정한다.

### 3.3 필요 경로 — "그 가격에 가려면 언제까지 무엇이 어디에 있어야 하나"

필요 경로는 **연간 한 점이 아니라 날짜별 경로**다. 기준 가격(기본 = 목표가 중앙값, 사람이 바꿈) 에 대해 세 경로를 만든다.

- **증권사 경로** — §3.1 의 열. 분기 추정치가 있는 증권사(사업부 표의 1Q26E~4Q27E 열) 는 분기 경로가 그대로 생긴다.
- **컨센 경로** — 기준을 통일한 증권사 경로의 중앙값. 분기 추정치가 없는 구간은 연간 값 사이를 **보간**하고 "보간" 표시를 붙인다(보간 방식은 §10 결정).
- **내 경로** — 계산기에 넣은 가정 묶음. 분기 경로는 컨센 경로 모양을 따라 비례 조정(사람이 바꿀 수 있다).

| 시점 | 26Q4 | 27Q1 | 27Q2 | 27Q3 | 27Q4 | 출처 |
|---|---|---|---|---|---|---|
| DRAM ASP 컨센 경로 (26Q3 = 100) | 108 | 115 | 122 | 128 | 132 | 유진·DS 분기 추정 (2곳) |
| DRAM ASP 내 Base 경로 | 108 | 112 | 116 | 120 | 122 | 계산기 (컨센 −8%) |
| 허용 띠 | ±5 | ±6 | ±7 | ±8 | ±8 | 사람 (기본 = 민감도 기준 제안) |

경로의 값은 **관측 지표와 같은 자**로 적는다(여기서는 기준 시점 = 100 인 가격 지수). 리포트가 "2027E DRAM 매출 458.5조" 만 주면 코드는 그것을 ASP 지수 경로로 바꾸지 못한다 — 그때는 "경로 없음 — 분기 추정치 또는 사람 입력 필요" 로 비워 둔다. 숫자를 만들어 채우지 않는다.

**도달 가능성.** 경로 옆에 최근 관측 추세를 놓는다. "27Q4 필요 132 · 최근 4분기 실제 +38%" 처럼. **"가능/어려움" 판정은 사람이 적고**, 코드는 두 숫자를 나란히 놓을 뿐이다.

### 3.4 증거 계획 — "그 경로 위에 있는지 무엇으로 아는가"

**관측값의 데이터 계약.** 관측값 하나는 다음 여덟 칸이 전부 있어야 저장된다.

| 칸 | 뜻 | 예 (DRAM ASP) |
|---|---|---|
| 지표 | 무엇을 쟀나 | DRAM 계약가 지수 |
| 기간 | 월 · 분기 · 연 | 월 (2026-10) |
| 값의 종류 | 절대값 · 증감률 · 누적 · 상태 | 지수 (26Q3 = 100) |
| 기준 | 없음 · QoQ · YoY · 컨센 대비 | 없음 (지수) |
| 관측일 | 실제로 관측된 날 | 2026-10-31 |
| 비교 시점 | 필요 경로의 어느 점과 비교하나 | 26Q4 |
| 출처 | 어디서 | DRAMeXchange 월간 |
| 검증 등급 | 확인됨 · 보도/추정 · 전망 | 확인됨 |

**같은 자 규칙.** 지표·값의 종류·기준이 필요 경로와 같을 때만 비교한다. "분기 QoQ +12%" 와 "2027E 경로" 는 비교하지 않는다 — 코드가 거부하고 "자가 다름" 을 표시한다. 상태형 지표(HBM4 인증 "진행 중/완료/지연") 는 숫자가 아니라 **일정표**와 비교한다: 필요 경로가 "인증 완료 26Q4 · 양산 27Q2" 이면 관측 상태가 그 날짜까지 그 단계에 도달했는가로 본다.

**검증 등급 규칙.** 신호등에는 **확인됨**(공시 · 공식 통계 · 회사 발표 · 기관 지수) 만 쓴다. 보도·추정은 회색으로 보이기만 하고, 전망은 필요 경로 쪽에만 쓴다. 리포트의 전망 수치는 관측값이 아니다.

**증거 계획 표.**

| 드라이버 (역할) | 지표 · 자 · 출처 · 주기 | 최근 확인된 관측값 (관측일) | 비교 시점의 필요값 (띠) | 경계 Bear / Bull | 다음 확인일 | 신호등 |
|---|---|---|---|---|---|---|
| DRAM ASP (핵심) | 계약가 지수 (26Q3 = 100) · DRAMeXchange · 월 | 107 (2026-10-31) | 26Q4 108 (±5) | 2개월 연속 하락 / 띠 위 2분기 | 2026-11-30 | 🟢 |
| HBM (필수) | 인증·양산 단계 · 회사 발표 · 분기 | 인증 진행 (2026-10-08) | 26Q4 인증 완료 | 지연 공시 / 조기 양산 | 2027-01-08 | 🟡 (단계 미도달 가능) |
| 파운드리 손익 (보조) | 분기 OP 조원 · 분기 실적 · 분기 | −0.4 (3Q26 확정) | 4Q26 −0.4 (±0.2) | 2027E −2 밑 / BEP | 2027-01-08 | 🟢 |
| 메모리 원가 (보조) | 감가상각비 YoY · 분기보고서 | — | — | — | — | ⚪ 관측값 없음 |
| FCF·주주환원 (보조) | 분기 FCF 조원 · IR | — | — | — | — | ⚪ |

**신호등 규칙** (코드). 확인된 관측값이 있고, 자가 같고, 비교 시점의 필요값과 띠가 있을 때만 켜진다.

- 🟢 비교 시점의 띠 안
- 🟡 띠 밖이지만 Bear 경계 안 · **또는** 띠 안이어도 **추세가 경로에서 멀어지는 중**(연속 2회 띠 하단 쪽으로 이동 — 핵심 지표가 경계 전에 빠르게 나빠지는 경우를 잡는다) · 또는 관측값이 오래됨(주기의 2배 초과)
- 🔴 Bear 경계를 넘음 → §3.5 의 규칙이 발동
- ⚪ 확인된 관측값 없음 · 자가 다름 · 필요값 없음 — "증거 없음" 이지 신호가 아니다

맵 전체의 신호등은 합산하지 않는다. "필수 🟡 1 · 핵심 🟢 1 · 보조 🟢 1 ⚪ 2" 처럼 **역할별로** 센다.

### 3.5 판단 수정 규칙 — "경계를 넘으면 무엇을 바꾸나"

**드라이버의 논제 역할** (사람이 정한다, A1 편집 폼).

| 역할 | 뜻 | 🔴 가 켜지면 |
|---|---|---|
| **필수 조건** | 이것 없이는 논제가 성립하지 않는다 (예: HBM4 양산) | **신규 BUY 보류** 플래그 자동 · 재검토 제안 |
| **핵심 수익 변수** | 기업가치를 크게 움직인다 (예: DRAM ASP) | 시나리오 재계산 · 확률 이동 **제안** |
| **보조 변수** | 영향이 제한적 (예: 파운드리 손익) | 경고 · 모니터링 주기 단축 제안 |
| **Kill 조건** | 논제를 근본적으로 무효화하는 **사실** (기존 A4.4) | 사람 확인 후 폐기 |

검증 규칙: 필수 또는 핵심이 하나도 없으면 미확정. 역할을 점수로 더하지 않는다.

**발동에서 판단 변경까지 (분리).**

```
 ① 감지   관측값이 경계를 넘음 (코드)
 ② 검증   진위(검증 등급 확인됨인가) · 기간(자가 같은가) · 지속성(연속 n회인가, 기본 2회) (코드 — 하나라도 아니면 "감지만, 미검증" 으로 멈춤)
 ③ 영향   어느 시나리오·어느 논제 문장이 걸리는가 (코드 — 규칙의 driver → 시나리오 가정·A0 문장 링크)
 ④ 제안   역할별 제안: 신규 BUY 보류 / 확률 이동 ○%p / 재검토 / 경고 (코드)
 ⑤ 승인   사람이 승인·거절 · 변경 이력에 기록 (사람)
```

④ 에서 자동으로 적용되는 것은 **필수 조건 위반 시 "신규 BUY 보류" 플래그** 하나뿐이다. 보조 변수는 경고로만 간다. 기존의 RR 미달 금지와 Kill 조건은 그대로다.

규칙은 지금의 If-Then 규칙 모양 그대로다(조건 · 대상 드라이버 · 역할 · 행동 · 상태). 조건에는 반드시 증거 계획의 **지표와 경계값과 지속성**이 들어가야 한다 — "분위기가 나쁘면" 같은 조건은 저장되지 않는다(검증 오류).

### 3.6 판단 상태 전이 — "분석 판단 · 보유 대응 · 주문은 다른 것"

이 시스템은 **주문을 내거나 막지 않는다.** 맵의 판단은 분석 판단이고, 보유 종목의 대응은 B 맵의 대응 매트릭스이며, 실제 매매는 사람이 다른 곳에서 한다. 세 층을 섞지 않도록 상태를 적는다.

| 층 | 상태 | 무엇이 바꾸나 | 자동 변경 |
|---|---|---|---|
| **A 맵 분석 판단** | BUY / WATCH / PASS + 플래그 {신규 BUY 보류, 재검토, 증거 없음} | 사람 (A6.5) · 플래그는 규칙 | 플래그만. 신규 BUY 보류 = 필수 조건 🔴 검증됨 ∨ RR 미달 ∨ 재검토 중. 판단값 자체는 사람이 바꾼다(보류 중엔 BUY 로 **저장되지 않음**, 기존 BUY 는 "BUY(보류)" 로 표시) |
| **B 맵 보유 대응** | hold / add / trim / exit / hedge / review | 대응 매트릭스(결과 상태등 × 원인 신호등) → 사람 | 없음. 매트릭스는 제안만 |
| **주문** | — | 사람, 시스템 밖 | 없음 |

"BUY 보류" 의 뜻은 **신규 매수 추천을 내지 않는다**는 것이다. 보유 중인 주식을 팔라는 뜻도, 추가 매수를 막는다는 뜻도 아니다 — 그것은 B 맵의 대응(원인 신호등이 B 의 매트릭스에 열로 들어간다) 이고, 최종 행동은 사람이다.

### 3.7 돌아가는 모양 (운영 루프)

```
 새 리포트 ──▶ Claim 추출·검증 ──▶ 가정 표 · 증권사 경로 · 컨센 경로 갱신
                                      │
 관측값 입력 ─── 데이터 계약 검사 ───┼──▶ 같은 자 비교 ──▶ 신호등
 (사람 · 수집기 · 에이전트)   (자 · 검증 등급)  │
                                      ▼
                              규칙 감지 ──▶ 검증 ──▶ 영향 ──▶ 제안 ──▶ 사람 승인 ──▶ 로그 · 상태 · 알림
```

리포트는 가정 표와 경로만 바꾸고, 관측값은 신호등과 규칙만 움직인다. 두 흐름을 섞지 않는다.

## 5. 삼성전자로 읽어 보기 (2026-10 리포트 3건, 숫자는 v6 §11 정규화 뒤 · 경로·띠·역할은 설명용 예시)

**가격.** 현재가 262,000 · 목표가 중앙값 530,000 · 컨센 EPS 85,798(2곳) · 목표가 유도 PER 6.18(순환).

**가정 표(§3.1).** 유진 560,000 — DRAM 가격 상승 지속 · 2027E OP 633조 · PER 는 말하지 않음. DS 530,000 — 2027E OP 612조 · 지배 NP 537.8조. IBK 460,000 — 2027E OP 572조 · 2028E 고점. 컨센 2027E DRAM 매출 458.5조(2곳) · HBM 82.9조(1곳 — 컨센 아님) · 파운드리 −0.57조.

**역산 표(§3.2).** 한 변수 해: DRAM ASP 만으로 262,000 → −56% (PER 6.18 고정) · PER 만으로 → 3.05 (실적 컨센 고정) · 파운드리만으로 → 범위 밖. 두 변수 조합(ASP × PER): (0%, 3.05) · (−14%, 3.5) · (−36%, 4.5) · (−56%, 6.18) 이 모두 262,000. **읽히는 것: 현재가는 "이익이 컨센대로 나와도 PER 3 대" 로도, "ASP 가 1/3 꺾이고 PER 4.5" 로도 설명된다.** 어느 쪽인지는 역산이 아니라 §3.1 의 증권사 PER 행(3.8 · 2.9 · 3.0 — 각 리포트 가격 기준) 과 관측값이 가려 준다 — 증권사 PER 행이 3 안팎이라는 것은 첫 번째 설명("이익은 믿지만 지속성은 안 믿음") 에 무게를 준다.

**필요 경로(§3.3, 기준 530,000).** 컨센 경로 = 2곳 분기 추정에서 DRAM ASP 지수 26Q4 108 → 27Q4 132(보간 없음), HBM 은 "26Q4 인증 완료 → 27Q2 양산"(DS · 유진 본문), 파운드리 분기 OP −0.4 → 27Q4 −0.1. 내 Base 경로는 컨센 −8%.

**증거 계획(§3.4).** DRAM ASP(핵심): 계약가 지수 107 (2026-10-31, 확인됨) vs 26Q4 필요 108 ±5 → 🟢. HBM(필수): "인증 진행" (2026-10-08 컨콜, 확인됨) vs 26Q4 "인증 완료" → 아직 기한 전이라 🟡(단계 미도달 가능). 파운드리(보조): 3Q26 확정 −0.4 vs 필요 −0.4 ±0.2 → 🟢. 메모리 원가·FCF(보조): ⚪. 맵 머리: "필수 🟡 1 · 핵심 🟢 1 · 보조 🟢 1 ⚪ 2".

**판단 수정 규칙(§3.5).** 핵심 — DRAM 계약가 2개월 연속 하락(확인됨) → 검증(지속성 2회) 통과 시 Base→Bear 10%p 이동 **제안**. 필수 — HBM4 인증 지연 공시 → 검증 통과 시 **신규 BUY 보류** 자동 + 재검토 제안. 보조 — 파운드리 2027E −2조 밑 → 경고. Kill — "2027E DRAM 계약가가 2026 평균 밑" 이 회사 발표·공식 통계로 확인 → 사람 확인 후 폐기.

**판단 상태(§3.6).** 보류 플래그 없음(필수가 🟡 이지 🔴 가 아님) · RR 은 사람이 확률을 넣어야 계산 · "증거 없음" 은 보조에만 있어 표시 안 함 → BUY 가 가능한 상태이고 판단은 사람이 한다. 보유 중이라면 B 맵 매트릭스에 원인 신호등(필수 🟡) 이 열로 들어가 "review" 가 제안된다.

## 6. 계산 규칙 (요약)

- **역산(한 변수)** — 가격 P = PER × EPS_std × (1 + ΔOP(x)(1−t) ÷ NP). ΔOP 는 각 변수에 1차식이므로 x 를 닫힌 식으로 푼다. 기울기 0 → "해 없음 — 필요 입력", 허용 범위 밖 → "범위 밖". 환원 변수는 역산 대상이 아니고, 수주 변수는 전환율·마진이 있을 때만 "기간 구조 단순화" 표시와 함께.
- **역산(두 변수)** — 변수 1 의 격자(기본 7점, 사람이 범위 지정) 마다 변수 2 를 위 식으로 푼다. PER 가 한 축이면 PER 격자에 대해 EPS 가 바로 나온다.
- **필요 경로** — 증권사 분기 추정치가 있으면 그대로, 연간만 있으면 보간(§10 결정) + "보간" 표시. 자(지표·값의 종류·기준) 를 경로 정의에 적고, 관측값과 같을 때만 비교한다.
- **신호등** — §3.4 규칙. 띠는 사람 입력(기본 제안 = 그 변수의 민감도로 "Base→Bear 가격 차이의 1/4" 에 해당하는 폭). 추세 판정 = 최근 2개 관측이 연속으로 경로에서 멀어짐. 나이 = 주기 × 2.
- **규칙 검증** — 등급 확인됨 ∧ 자 같음 ∧ 연속 n 회(기본 2). 하나라도 아니면 "감지만".
- **보류 플래그** — 필수 🔴 검증됨 ∨ RR 미달 ∨ 재검토 중. 판단값은 바꾸지 않는다.
- **확률 이동** — 규칙에 적힌 %p 를 그대로 제안(자동 추론 없음).

## 8. 받지 않는 것

- **자동 확률 갱신** (베이즈·점수 모델): 규칙에 적힌 %p 제안까지만.
- **LLM 이 경계값·띠·필요값·관측값을 쓰는 것**: 숫자 생성 금지 원칙 그대로.
- **주가를 증거로 쓰는 것**: 손절 규칙(A6.3) 에만.
- **자동 Kill · 자동 판단 변경**: 자동은 보류 플래그 하나뿐.
- **신호등·역할의 점수 합산**: 역할별 대응만.
- **주문 차단·승인**: 이 시스템엔 주문이 없다.
- **보간으로 만든 경로를 "증권사 전망" 처럼 보이는 것**: 보간은 항상 표시.

## 10. 정해야 할 것 (사용자)

1. **필요 경로의 기준 가격** — 목표가 중앙값 기본(권고) 과 내 목표가 둘 다 보일지.
2. **두 변수 조합의 기본 쌍** — 핵심 수익 변수 × 적용 PER(권고).
3. **보간 방식** — 연간 값 사이를 등비(권고 — 가격·물량 경로에 자연) / 등차, 항상 "보간" 표시.
4. **허용 띠 제안** — 민감도 기준 "Base→Bear 가격 차이의 1/4" 폭을 제안값으로(권고) / 공란.
5. **지속성 기준** — 규칙 검증의 연속 횟수 기본 2(권고).
6. **역할 기본값** — 섹터 KPI 사전의 첫 번째를 핵심, 정성 드라이버를 필수 후보로 제안(권고 — 사람이 확정) / 전부 공란.
7. **관측값 입력 경로** — 처음엔 사람 입력(편집 폼·CLI) 만(권고), 수집기·에이전트 입력은 W5.
8. **신설 노드** — A2.4 · A4.6 신설(권고).

결정이 오면 W0 → W1 순으로 간다.

## 11. 검토 의견 반영 (2026-10-27) — 무엇이 바뀌었나

| 지적 | 판정 | 반영 |
|---|---|---|
| **1. 역산이 '하나의 정답' 처럼 보인다** | 맞다. 초안 §3.1 은 증권사 전망과 역산 해를 한 표에 섞었다 | 가정 표(실제 전망 + 내 가정) 와 역산 표(한 변수 해 · **두 변수 조합**) 를 분리(§3.1·§3.2). 모든 역산 숫자에 해석 범위 4종 표시. "단조이므로 이분 탐색" 을 지우고 **선형 닫힌 식 + 해 없음/범위 밖 + 템플릿별 예외**(환원은 역산 없음, 수주는 조건부) 로 바꿈 |
| **2. 신호등이 다른 시점·다른 지표를 비교한다** | 맞다. 초안 예시가 분기 QoQ 를 연간 경로와, 상태를 일정과 섞어 비교했다 | 관측값 **데이터 계약 8칸**(지표·기간·값의 종류·기준·관측일·비교 시점·출처·검증 등급), **같은 자 규칙**, **날짜별 필요 경로**(분기 추정치 → 보간 표시), 상태형 지표는 일정표와 비교, **확인됨 등급만 신호등에**, 추세 판정 추가(§3.3·§3.4). 단계 순서를 증거 계약(W1) → 역산(W2) → 규칙(W3) 으로 바꿈 |
| **3. 신호등 하나로 BUY 차단은 경직** | 맞다 | 드라이버 **논제 역할**(필수·핵심·보조·Kill) 과 역할별 대응, **감지→검증→영향→제안→승인** 분리, 자동은 "신규 BUY 보류" 플래그뿐, **분석 판단 / 보유 대응 / 주문** 세 층의 상태 전이표(§3.5·§3.6). RR 미달·Kill 은 그대로 |
