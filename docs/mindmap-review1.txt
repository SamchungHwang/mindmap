# 증권사 리포트 기반 투자 마인드맵 전면 재설계안

## 1. 설계 방향을 수정하겠습니다

말씀하신 대로 이 시스템의 목적은 여러 증권사의 기업분석 리포트를 취합해 투자 의사결정에 활용할 수 있는 마인드맵을 자동 생성하는 것입니다.

제가 앞서 제안한 독립적인 실적 예측 엔진, 산업별 재무모델, 시장 내재 기대 역산은 장기적인 투자 AI 시스템에는 유용하지만, 현재 프로젝트의 범위를 지나치게 확대하는 방향이었습니다.

이번에는 다음 세 가지 전제를 명확히 하겠습니다.

1. 입력: 같은 종목에 대한 여러 증권사의 기업분석 리포트
2. 처리: 리포트별 사실·전망·논거를 추출하고, 공통점과 차이점, 핵심 투자변수를 분석
3. 출력: 증권사들의 전망을 종합하되, 투자자가 자신의 판단을 추가할 수 있는 A형 투자 마인드맵

핵심은 리포트의 평균값을 만드는 것이 아닙니다.

여러 애널리스트가 같은 기업을 어떻게 보고 있는지, 어디에서 의견이 일치하고 무엇 때문에 전망이 달라지는지를 구조화하는 것입니다.

제가 처음부터 다시 만든다면 시스템의 중심을 다음과 같이 정의하겠습니다.

Report-to-Investment-Mindmap

증권사 리포트 3\~10건

동일 종목 · 서로 다른 증권사 · 서로 다른 작성 시점

리포트별 투자 주장과 수치 추출

목표주가 · 실적 전망 · 핵심 논거 · 리스크 · 촉매

증권사 간 비교·종합

공통 전망 · 핵심 이견 · 가정 차이 · 전망 변화

투자 논제와 시나리오 초안 생성

핵심 드라이버 · Bear/Base/Bull · 확인 조건

A형 투자 마인드맵

증거가 연결된 초안 · 사람의 최종 판단

여기서 중요한 설계 원칙은 리포트의 주장을 충실히 보존하되, 리포트에 없는 투자 판단을 사실인 것처럼 생성하지 않는 것입니다.

## 2. 가장 중요한 변경: '문장 추출'이 아니라 '투자 주장 추출'

첨부 개선안 A에서는 리포트 문장을 LLM으로 분류해 `risk`, `thesis`, `catalyst` 등의 유형을 부여합니다.

방향은 맞지만, 저는 여기서 한 단계 더 나아가겠습니다.

리포트의 개별 문장이 아니라 투자 주장(Investment Claim) 을 기본 분석 단위로 삼겠습니다.

예를 들어 다음과 같은 문장이 있다고 가정하겠습니다.

> HBM4 공급 확대와 제품 믹스 개선으로 2027년 메모리 영업이익이 증가할 전망이다.

이 문장을 단순히 `thesis`로 분류하면 투자 판단에 활용할 수 있는 정보가 제한적입니다.

반면 다음처럼 구조화하면 훨씬 유용해집니다.

| 속성    | 추출 결과                   |
| ----- | ----------------------- |
| 주장    | HBM4 공급 확대가 영업이익 증가를 견인 |
| 핵심 변수 | HBM4 공급량, 제품 믹스         |
| 영향 대상 | 메모리 사업부 영업이익            |
| 방향    | 긍정적                     |
| 예상 시점 | 2027년                   |
| 주장 유형 | 증권사 전망                  |
| 출처    | 증권사·리포트·페이지             |
| 정량 근거 | 해당 리포트에서 확인된 수치만 연결     |

이렇게 하면 여러 증권사의 서로 다른 문장을 하나의 투자 이슈로 묶을 수 있습니다.

가령 5개 증권사가 HBM4를 언급하더라도 실제 주장은 다를 수 있습니다.

- A증권사: 공급량 증가가 핵심
- B증권사: 판매가격 상승이 핵심
- C증권사: 생산 수율 개선이 핵심
- D증권사: 경쟁사 공급 지연이 핵심
- E증권사: 고객사 인증이 아직 위험 요인

이 다섯 개를 단순히 'HBM4 긍정 4건, 부정 1건'으로 요약하면 중요한 정보를 잃습니다.

공통 주제는 HBM4이지만, 전망을 결정하는 원인과 가정이 서로 다르기 때문입니다.

따라서 새로운 추출 모델은 다음 네 가지를 구분해야 합니다.

`Claim → Driver → Assumption → Expected Impact`

이 구조가 새로운 Mindmap의 핵심 데이터 모델이 되어야 합니다.

## 3. 여러 리포트를 취합하는 방법도 달라져야 합니다

저는 리포트 취합을 세 단계로 나누겠습니다.

### 3.1 수치 통합

목표주가, 매출액, 영업이익, EPS 등을 증권사별로 정리합니다.

여기서 중요한 것은 단순 평균 이전에 동일 기준으로 비교할 수 있는지를 확인하는 것입니다.

예를 들어 2027년 영업이익 전망이라도 연결 기준인지, 특정 사업부 기준인지, 일회성 비용을 포함했는지에 따라 비교 가능성이 달라집니다.

기본 규칙은 다음과 같습니다.

- 증권사별 최신 리포트 1건을 대표값으로 사용
- 과거 리포트는 전망 변경 이력으로 보존
- 회계 기준·기간·단위가 같은 값만 집계
- 평균뿐 아니라 중앙값·최솟값·최댓값·표본 수를 표시
- 작성일이 오래되었거나 주요 실적 발표 이전의 전망은 별도 표시

이 접근은 실제 컨센서스 데이터 서비스의 방식과도 부합합니다. 예를 들어 LSEG의 StarMine은 애널리스트의 과거 정확도와 추정치 최신성 등을 고려하고, FactSet도 증권사별 추정치와 집계값을 구분해 관리합니다.&#x20;

### 3.2 투자 논거 통합

이 단계가 가장 중요합니다.

동일한 주제에 대한 증권사들의 주장을 비교해 다음 네 가지로 정리합니다.

| 구분      | 의미                 |
| ------- | ------------------ |
| 공통 견해   | 여러 증권사가 같은 방향으로 전망 |
| 핵심 이견   | 방향 또는 규모에 실질적인 차이  |
| 독립적인 주장 | 일부 증권사만 제시한 중요한 관점 |
| 미해결 쟁점  | 자료만으로 판단하기 어려운 사항  |

특히 독립적인 주장을 평균 속에 묻어서는 안 됩니다.

증권사 5곳 중 4곳이 같은 전망을 하고 1곳만 다른 전망을 하더라도, 그 한 곳이 중요한 선행지표를 근거로 제시했다면 투자 판단에서 더 중요할 수 있습니다.

따라서 단순 언급 횟수보다 근거의 구체성, 수치와의 연결성, 다른 전망을 설명하는 능력을 우선하겠습니다.

### 3.3 전망 변화 통합

첨부 개선안에서 가장 발전시킬 가치가 큰 부분은 리비전(Revision)입니다.

단순히 목표주가가 상향되었다는 사실만으로는 부족합니다.

다음 질문에 답해야 합니다.

- 목표주가가 왜 바뀌었는가?
- 영업이익 전망이 바뀌었는가?
- 적용 PER이 바뀌었는가?
- 기존 투자 논제가 강화되었는가?
- 리스크가 새롭게 발생했는가?

예를 들어 목표주가가 30만 원에서 40만 원으로 상향되었다면, 실적 전망 상향과 밸류에이션 배수 상향을 구분해야 합니다.

리포트에 그 근거가 없다면 '상향 이유 확인 불가'로 표시해야지 AI가 임의로 설명해서는 안 됩니다.

## 4. 새로운 마인드맵은 어떤 구조가 좋을까?

기존 A0\~A8을 유지하더라도 내부 의미를 상당 부분 바꾸겠습니다.

특히 A2를 '시장이 믿는 것 vs 내가 다르게 보는 것'에서 '증권사 컨센서스와 이견' 중심으로 재구성하는 것이 적합합니다.

시장 전체의 기대를 몇 개 증권사 리포트만으로 확정할 수 없기 때문입니다.

이 구조는 기존 A 맵과 호환 가능한 방향이면서도, 각 노드의 내용이 증권사 리포트로부터 어떻게 생성됐는지 설명할 수 있습니다.

### 가장 중요한 A1과 A2의 관계

A1에는 핵심 드라이버를 놓고, A2에는 그 드라이버에 대한 증권사들의 견해를 놓겠습니다.

예를 들어 A1.1이 'HBM4 공급 확대'라면 A2에는 해당 변수에 대한 증권사별 가정과 전망 차이를 연결합니다.

이렇게 해야 마인드맵이 단순한 항목 나열이 아니라 원인과 의견 차이가 연결된 투자 분석 구조가 됩니다.

## 5. Bear/Base/Bull을 어떻게 만들 것인가?

이 부분은 기존 설계를 크게 수정해야 합니다.

첨부의 현재 방식은 증권사 목표주가 분포를 이용해 Bear/Base/Bull을 만듭니다.

그런데 삼성전자 실제 리포트 3건의 목표주가가 46만\~56만 원이라면, 이를 이용해 만든 Base와 Bull은 매우 가까워질 수 있습니다.

이것은 세 가지 경제적 시나리오가 아니라 세 증권사의 목표주가 차이를 보여주는 것에 불과합니다.

따라서 목표주가 분포와 경제적 시나리오를 분리하겠습니다.

### 첫 번째: 증권사 목표주가 분포

| 지표     | 표시 내용               |
| ------ | ------------------- |
| 최소·최대  | 가장 보수적·낙관적인 증권사 목표가 |
| 평균·중앙값 | 표본의 중심              |
| 분산     | 증권사 간 의견 차이         |
| 리비전    | 상향·하향 방향과 크기        |

이는 리포트에서 직접 산출할 수 있습니다.

### 두 번째: Bear/Base/Bull 시나리오

시나리오를 만들기 위한 가정이 리포트에 충분히 있다면 다음처럼 구성합니다.

- Bear: 보수적인 실적 전망과 그 근거
- Base: 여러 증권사가 공통으로 제시하는 중심 전망
- Bull: 낙관적인 실적 전망과 그 근거

단, 해당 리포트에 시나리오별 목표가가 없으면 자동으로 정교한 목표가를 만들어서는 안 됩니다.

리포트의 EPS와 PER 등을 이용해 계산한 값은 시스템 계산치로 표시하고, 증권사가 직접 제시한 목표가와 구분해야 합니다.

또한 확률 30/45/25를 기본값으로 강제하지 않겠습니다.

증권사 리포트만으로 시나리오 발생 확률을 객관적으로 도출하기 어렵기 때문입니다.

따라서 확률이 없는 상태에서는 기대수익률 계산을 보류하고, 사용자 또는 별도의 확률 모델이 값을 제공할 때 계산하도록 하겠습니다.

이렇게 하는 것이 실제 투자에서 잘못된 정밀도를 피하는 방법입니다.

## 6. LLM은 한 번에 마인드맵을 만들게 하지 않겠습니다

첨부 개선안 A는 기존 6개 그룹별 LLM 호출을 활성화하고 문장 분류를 추가하는 방식입니다.

저는 처음부터 만든다면 다음처럼 책임을 나누겠습니다.

| 단계     | 처리 방식        | 결과          |
| ------ | ------------ | ----------- |
| PDF 읽기 | PDF 파서       | 문단·표·페이지    |
| 숫자 추출  | 규칙 + LLM 보조  | 목표가·실적·EPS  |
| 주장 추출  | LLM          | 투자 주장과 근거   |
| 주장 통합  | LLM + 의미 검증  | 공통점·이견·쟁점   |
| 수치 집계  | Python       | 컨센서스·분산·리비전 |
| 노드 생성  | 결정론적 매핑      | A0\~A8      |
| 최종 검증  | 스키마·출처·수치 검사 | 경고·미확인 항목   |

LLM은 의미를 해석하고 종합하는 데 집중하고, 숫자와 구조를 확정하는 작업은 코드가 담당합니다.

특히 LLM이 리포트에 없는 새로운 사실을 생성하지 못하도록 모든 주요 주장을 원문 페이지 또는 표와 연결해야 합니다.

LLM이 '여러 증권사가 HBM4 공급 확대를 긍정적으로 전망한다'고 생성했다면, 실제로 어느 증권사의 어떤 문장을 근거로 했는지 확인할 수 있어야 합니다.

## 7. 신규 리포트가 들어올 때의 동작

첨부 개선안 C는 기존 마인드맵의 `draft` 태그를 확인하고 일부 노드를 갱신하는 방식입니다.

저는 기존 맵과 새로운 리포트 분석 결과를 직접 병합하지 않겠습니다.

대신 다음과 같이 처리하겠습니다.

기존 마인드맵 V1

## 8. 개발 우선순위는 이렇게 정하겠습니다

처음부터 다시 개발하더라도 현재의 실제 PDF 13건과 세 종목은 매우 유용한 테스트 자료입니다.

다만 구현 전에 13건의 정답표를 먼저 만들어야 합니다.

| 단계 | 개발 내용               | 완료 기준            |
| -- | ------------------- | ---------------- |
| P0 | 실제 PDF 정답 데이터셋      | 수치·주장·페이지 정답 확보  |
| P1 | 문서 추출·수치 표준화        | 증권사별 추정치 정확하게 비교 |
| P2 | Investment Claim 추출 | 주요 주장·근거·시점 연결   |
| P3 | 증권사 간 주장 통합         | 공통점·이견·독립 주장 구분  |
| P4 | A0\~A8 자동 생성        | 근거가 연결된 맵 생성     |
| P5 | 증분 업데이트             | 사용자 수정 보존·변경안 제시 |
| P6 | GUI 및 품질 평가         | 원문 확인·승인·수정 이력   |

저는 P2와 P3를 가장 중요한 개발 과제로 보겠습니다.

PDF에서 목표주가를 정확히 읽는 것은 필수 조건이지만, 그것만으로는 좋은 투자 마인드맵이 되지 않습니다.

반대로 서로 다른 증권사의 핵심 논거를 제대로 연결하면 단순한 컨센서스 표보다 훨씬 가치 있는 결과를 얻을 수 있습니다.

### 평가 기준

단순히 '사용자가 몇 개 노드를 수정했는가'보다는 다음 지표를 우선하겠습니다.

- 핵심 투자 주장 재현율: 중요한 주장을 빠뜨리지 않았는가
- 근거 정확도: 주장과 연결된 원문이 실제로 그 내용을 뒷받침하는가
- 이견 식별 정확도: 증권사 간 차이를 제대로 발견했는가
- 수치 정확도: 기간·단위·회계 기준이 일치하는가
- 마인드맵 활용성: 투자자가 핵심 변수와 쟁점을 빠르게 파악할 수 있는가

목표주가 예측의 정확도나 실제 투자수익률은 별도의 투자 시스템 평가에 속합니다. 이 프로젝트의 1차 성공 기준은 리포트에 포함된 투자 정보를 얼마나 정확하고 유용하게 종합했는가여야 합니다.

## 9. 최종 제안: 이 시스템의 차별화 요소 세 가지

① Consensus보다 Disagreement

증권사 목표가 평균보다, 왜 서로 다른 전망을 하는지 설명하는 기능에 집중합니다. 특히 낙관·비관의 원인이 되는 핵심 가정을 찾아내야 합니다.

② Summary보다 Causal Structure

리포트 문장을 요약하는 데 그치지 않고, 핵심 드라이버가 실적과 목표주가에 어떤 영향을 준다고 주장하는지 연결합니다. 단, 리포트가 제시하지 않은 인과관계는 추론으로 구분합니다.

③ Static Map보다 Evolving Map

새로운 리포트가 들어올 때마다 전체 내용을 덮어쓰지 않고, 전망 변화와 새롭게 등장한 투자 쟁점을 추적합니다.

## 최종 결론

기존 개선안 A\~L을 단순히 구현하는 것보다 Investment Claim 중심으로 데이터 구조를 다시 만드는 것이 가장 효과적인 재설계라고 판단합니다.

다만 범위는 명확히 제한하겠습니다.

증권사 리포트를 입력으로 받고, 증권사들의 실적 전망과 투자 논거를 비교·종합하여, 투자자가 자신의 판단을 추가할 수 있는 A형 마인드맵을 만드는 데 집중합니다.

독립적인 실적 예측 모델이나 외부 산업 데이터 수집은 이 시스템의 필수 구성요소가 아닙니다.

개발 순서는 '리포트별 주장 추출 → 증권사 간 공통점·이견 분석 → 수치 컨센서스 통합 → 근거 기반 A0\~A8 생성 → 신규 리포트 변화 추적'을 권합니다.

이렇게 설계하면 기존의 '리포트 여러 개를 평균 내서 마인드맵에 채우는 프로그램'에서 여러 애널리스트의 투자 논리를 비교하고 종합하는 AI 리서치 시스템으로 발전할 수 있습니다.
